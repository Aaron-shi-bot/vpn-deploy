# 单台 VPS 直连、应用代理与账号边界

本技能默认处理本机直接连接一台 VPS、由该 VPS 访问目标服务的个人代理方案。v2rayN 在本机管理客户端内核；3x-ui 在同一台 VPS 上管理 Xray。面板不是额外的数据转发节点，SSH 管理连接也不是日常代理流量必经的中转。

## 判断现有结构

区分已知事实与配置推断。客户端未配置前置代理，只能支持“本地未见主动增加的前置跳点”；若没有查看服务端出站、隧道或 NAT，不能据此断言整个服务端链路绝无中转。核对真实出口时使用已明确的代理路径，并分别看 IPv4/IPv6 和目标应用，不以浏览器一次查询代替整机验证。

只讨论国家无关的结构时，不自动引入地区推荐。用户已有 VPS 时保留其服务商和地区；不要用固定商家排名、IP 类型或旧价格替代当前证据。

## 何时考虑多一跳

本机直连已满足需要时，默认保留单台结构。只有明确的问题和测量支持时，才讨论机场入口或自建中转，例如本机到最终出口的路径不可达或质量差，而另一路径表现更好。比较实际应用表现、费用、维护负担及新增故障点，不把串联两台机器称为自动冗余或自动更稳定。

如果前置入口改变而最终出口仍是同一公网 IP，目标服务在连接层看到的来源仍是该出口。连接时序等表现可能变化，因此也不能声称所有风控信号或封号概率完全相同；能得出的结论是：**没有依据仅凭多一跳就宣称账号风险下降。**

网络访问受阻与平台地区、账号、使用规则是不同问题。中转可能改变网络可达性，不自动改变使用资格或满足平台条款。平台也没有要求所有用户必须采用多跳结构。

## Claude 与 Codex 应用验收

- 本机浏览器、CLI、桌面应用和云端执行环境分别判断。云端任务或远端连接器的出口由其执行环境决定，本机 v2rayN 不自动覆盖它们。
- 系统代理只对遵循该设置的程序有效；路由界面的“全局”不代表所有程序已接管。TUN 也要按实际路由、DNS、IPv6 与绕过规则验证。
- Claude Code 的[官方网络文档](https://code.claude.com/docs/en/network-config)列出 HTTP/HTTPS 代理环境变量，并说明不直接支持 SOCKS 代理。使用本机已验证的 HTTP/mixed 端口，检查大小写环境变量与 NO_PROXY 的优先级，在启动进程前设置；桌面应用管理的会话还需遵循对应设置范围。
- Codex 的本地 CLI、桌面应用、登录流程与云端任务不能混为一个进程。按对应版本官方说明检查代理支持，不能把 Claude Code 的环境变量规则直接当成所有 Codex 组件的规则。
- 应用认证、权限、额度与频率错误应按实际响应解释。单个 403、429、浏览器挑战或网络超时，均不足以直接断言账号永久封禁。

## 用户关心封号时怎么回答

先回答网络拓扑能改变什么，再说明证据限制，不继续用断流或延迟回答账号问题。

“只看最后一跳 IP”过度简化了平台判断。Anthropic 的[隐私政策](https://www.anthropic.com/legal/privacy)还涉及设备、连接与使用信息；其[申诉说明](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)列出使用政策、账号创建地区及条款问题。信息收集清单不等于已公开风控权重，也不能编造各因素的封号概率。

不把独享、住宅、低风险评分或增加中转写成防封保证。不建议仅为“防封号”购买第二台机器。独立 UUID 只改变代理认证、统计和撤销粒度，不给每个使用者自动分配独立公网出口，也不使目标平台账号彼此完全隔离。

来源核对日期：2026-10-23；平台规则与应用代理能力可能变化，执行时按对应官方页面和实际版本核对。
